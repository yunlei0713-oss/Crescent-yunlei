| P4 | Pi 保持阈值及溢出调度，宿主记录质量结果、限制重复阈值压缩并处理超时。上下文按当前消息、近期原文、检查点、已批准记忆组织。补充资料只进入当次模型请求，参与系统提示、工具 schema、输出预留和安全余量计算。无相关资料时不生成空区块。旧侧栏摘要改为本地生成，自动学习关闭时不再因更新侧栏摘要调用模型。 |

## 数据迁移与恢复

主历史库 `crescent.db` 在原有初始化入口应用带版本号的增量事务。新增检查点、修订号、FTS5、索引进度及待处理变更，以及记忆清理队列。回填按当前会话在搜索时分批完成，应用启动无需索引历史正文。原始日志内容在迁移时保持原样，旧会话的别名与原有 ID 可继续读取。检查点来源使用复合身份，避免旧 tab 上重复的数字日志 ID 串用。

`memory.db` 用 `user_version` 管理增量迁移，增加类型、时间、有效期、替代关系和证据引用。反思复用原有记忆关系表。无变更的旧学习标记继续兼容。旧 schema 夹具验证保留正文及批准状态，另通过故障迁移验证事务回滚。

删除会话时，主库先提交原文与新派生数据的删除，持久化队列再清理记忆库。清理完成后才确认请求成功。两个库之间不假设原子事务，重试是幂等的。跨库清理积压或报错时，记忆读取停止使用未核实的来源。单源观察及依赖它的反思会被删除，多源观察移除失效证据后进入重新审核。显式历史删除也丢弃该会话当前 Pi 投影。既有独立的人工运维反馈按原产品生命周期保留。

备份与回退使用同一时点的两库。先退出墨巡，备份整个应用数据目录及其中存在的 WAL/SHM 文件，或对已停止写入的两个库分别做 SQLite 一致性备份。回退时将两库一同恢复，避免版本与跨库引用不一致。本次验收使用合成旧库副本，未迁移用户日常使用的数据目录。

## 验收边界与后续建议

- `history_search` 只检索当前授权会话。要跨会话查阅原文，可通过已有历史入口打开目标会话。连接范围内可跨会话召回已批准的知识。索引保留每条消息的有界正文，单次回填有批次和时间上限，未完成会明确返回索引未完成状态。超长原文仍可在会话历史中查看。
- 保护清单使用确定性规则和有限窗口，精确验证只覆盖已收录的事实。模型的自由文本可能遗漏事实或添加推断，部分通过时依靠有来源的检查点与原文召回。反思仍需人工判断归纳是否成立。自动压缩沿用 Pi 原生摘要指令，手动压缩附加墨巡结构化要求。
- 新增派生数据使用保守脱敏，已存在的原始日志在迁移中保留。自然语言中的无标记业务机密无法由规则完整识别。后续可用更长的脱敏运维样本扩展秘密格式、长命令和中英文混合查询覆盖。
- 实施前完成了 CI 和本地回归基线，但没有保存同组模型夹具的时延与 Token 数据。下列性能测量作为本次实现的合成基线，不能推断生产压缩率、模型质量或费用。上线前可用实际旧版本的脱敏数据库副本演练升级与回退，并用本地模型补测自由摘要和推理质量。
