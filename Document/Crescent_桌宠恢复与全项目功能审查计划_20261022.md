## 二、审查确认的桌宠故障

### 2.1 已确认的根因：桌宠开关依赖额度监控端点

相关位置：

- src/renderer/src/App.tsx：whaleEnabled 状态约第 492 行；toggleWhaleMonitor 约第 2846 行；顶部桌宠按钮约第 5580 行；桌宠组件条件挂载约第 6271 行。
- src/main/whale-monitor.ts：save-settings IPC 约第 25 行；validateSettingsInput 约第 60 行；validateEndpoint 约第 115 行。
- src/shared/whale-monitor.ts：DEFAULT_WHALE_MONITOR_CONFIG。
- src/renderer/src/components/WhaleMonitor.tsx：设置保存约第 421 行；组件渲染门槛约第 541 行。

当前代码链路：

1. 默认 Whale Monitor 配置中的 spendBaseUrl 和 modelsBaseUrl 允许为空，且默认值就是空字符串。
2. App.tsx 的桌宠按钮调用 toggleWhaleMonitor；该函数读取额度监控快照，再调用 saveSettings 修改 enabled。
3. 主进程 validateSettingsInput 在处理开关状态之前，无条件验证 spendBaseUrl 和 modelsBaseUrl。空的用量端点会直接抛出 “Enter the spend endpoint URL in whale monitor settings.”。
4. 保存失败后，toggleWhaleMonitor 不会更新 whaleEnabled，桌宠组件也就不会挂载。
5. 额度监控设置入口位于 WhaleMonitor 组件内部，形成“必须先打开桌宠才能配置端点，但打开桌宠又要求先配置端点”的死循环。
6. WhaleMonitor 组件还用 snapshot.settings.enabled 决定是否返回 null，把“宠物是否显示”和“额度监控是否启用”混成了一个状态。

这与截图中的错误文案完全吻合。应按以上链路修复，而不是给用户强行填入某个未知或不可访问的默认 URL。

### 2.2 P0 修复目标：拆分桌宠可见状态和额度监控状态

采用以下职责划分：

- **桌宠可见性（petVisible）：** 只控制鲸鱼娘浮层是否显示，不调用 save-settings，不依赖 API Key、用量端点或模型端点。
- **额度监控启用状态（monitor enabled）：** 只控制主进程额度数据轮询；是否显示桌宠不再由此状态决定。
- **端点与凭据配置：** 仅影响用量查询、模型查询和轮询；配置缺失不能阻止桌宠显示、动画、拖拽或打开设置面板。

具体实现要求：

1. 将 App.tsx 的 toggleWhaleMonitor 改为只切换 petVisible；不得通过 saveSettings 来实现桌宠显示/隐藏。
2. petVisible 可以继续沿用“每次启动默认隐藏”的现有产品行为，也可以作为独立的应用偏好持久化；优先采用独立持久化字段，默认值保持 false，避免把用户是否看见桌宠写进额度监控 enabled。不得复用 WhaleMonitorConfig.enabled 表示两个含义。
3. WhaleMonitor 组件不应因 settings.enabled 为 false 而完全不渲染。只要用户开启 petVisible，就应能显示基础桌宠和打开设置；监控未配置时展示明确的“额度监控未配置”状态。
4. 调整主进程端点校验：保存一般设置或桌宠显示状态时，空端点应允许存在；非空端点仍必须校验 URL 格式、HTTP/HTTPS 协议和禁止 URL 内嵌凭据。执行 refresh-usage / refresh-models 前仍须检查所需端点和 API Key，并给出可操作的中文错误。
5. 调度器只有在监控启用、API Key 存在且对应端点有效时才发起网络请求。配置不完整时不得启动无效轮询，也不得影响应用启动或桌宠渲染。
6. 设置面板在端点未配置时仍可打开。保存预算、刷新间隔、日期等普通设置时，不应因为另一项端点为空而产生误导性错误；用户主动刷新时才明确提示缺失的配置项。
7. 保持 API Key 的加密存储、脱敏日志和 IPC 安全边界，不要把密钥放入 renderer 日志、toast、URL 或普通配置导出。
8. 处理快照初始化竞态：组件首次打开时，应有静态待机图或轻量加载状态；快照获取失败时显示可恢复错误，而不是无提示空白。
9. 继续保留当前按需加载设计：WhaleMonitor 是 lazy import，src/renderer/src/components/whale/registry.ts 的 WebM 资源在桌宠界面打开时才参与加载。不要为了修复按钮而把整套动画提前打进首屏。

### 2.3 P0/P1 自动化回归用例

必须覆盖：

- 默认端点为空、API Key 为空时，首次点击桌宠按钮成功显示宠物，且不调用 save-settings。
- 显示/隐藏/再次显示均可用，不弹出 spend endpoint 错误。
- 额度监控关闭时，桌宠仍可显示；设置面板仍可打开。
- 端点未配置时，轮询不会发起网络请求；用户主动刷新会得到明确的配置提示。
- 有效端点、有效 API Key 的配置仍可保存、刷新用量和模型列表。
- 非法协议、带用户名密码的 URL、超长 URL、非法预算、非法刷新间隔仍被拒绝。
- 主进程保存设置失败时，界面显示错误并保留用户输入，不会把组件卡在无法再次打开的状态。
- 桌宠可见性持久化行为符合最终选择；若持久化，验证重启后的默认/保存行为。
- 动画文件加载失败时回退到静态待机图，不产生 React 未捕获异常。
- 不需要访问真实 LiteLLM 或生产服务；使用 mock 或本地测试桩。

建议新增或补齐 whale-monitor 的纯函数/IPC 单测和 WhaleMonitor 组件测试。不要只依赖人工点按钮验收。

## 三、左下角工具栏改造

### 3.1 目标布局

用户指定的三个入口：

1. 桌宠开关；
2. 主题切换；
3. Crescent GitHub 链接： https://github.com/aide-family/Crescent 。

将桌宠开关和主题切换从右上角移到左下角，并新增 GitHub 图标按钮。右上角保留连接、MCP、Skills、历史、记忆、本地资料、命令手册、Wiki、面板交换、语言和设置等其他入口。

视觉风格与现有 app-commandbar 一致：紧凑图标按钮、透明背景、hover 使用 accent、明确的 tooltip/title、统一焦点环和禁用状态。

### 3.2 布局与组件要求

1. 当前截图中的左下角区域属于终端的子终端栏；src/renderer/src/components/SubterminalPanel.tsx 内已有“子终端”标题、添加、折叠和关闭按钮。不能用新工具栏覆盖或替换这些功能。
2. 工具栏应锚定应用窗口左下角，而不是绑定到 TerminalPane 内部；否则当用户交换终端/对话顺序，或切换到仅对话布局时，工具栏可能移动到右侧或消失。
3. 优先在 App.tsx 的应用外壳增加独立的左下角工具栏/底栏，或在现有底部视觉栏中划出独立区域；如果新增独立底栏，必须给 app-frame 预留高度，不能覆盖终端输出、子终端标题、输入区或对话输入区。
4. 不论子终端数量为 0、1、2、3，子终端展开/折叠，终端与对话交换顺序，或切换 terminal/chat/split 布局，都不得出现按钮重叠、遮挡、被裁切或无法点击。
5. 桌宠按钮使用 WhalePetPortrait，按 petVisible 显示“显示桌宠/隐藏桌宠”状态；点击不得触发额度端点校验。
6. 主题切换继续复用 ThemeSwitcher 和现有 APP_THEME_OPTIONS，不要复制一份主题逻辑。ThemeSwitcher 目前菜单使用 top-full right-0；移到左下角后必须增加合适的 placement/对齐方式，让菜单从按钮上方展开并向右展开，确保完整落在视口内。
7. ThemeSwitcher 的 Escape 关闭、外部点击关闭、键盘焦点返回、aria-expanded/aria-controls/aria-pressed 行为必须继续有效。
8. GitHub 按钮使用 lucide-react 的 GitHub 图标，title 和 aria-label 应表达“打开 Crescent GitHub 仓库”；点击后使用现有的 window.api.app.openExternal，通过主进程已存在的 app:open-external / openExternalUrlIfAllowed 安全路径打开固定 URL。不得直接在 renderer 调用 Electron shell，不要为固定链接新增绕过现有安全检查的 IPC。
9. 如果 openExternal 返回失败，显示简短错误提示；成功时不需要多余弹窗。
10. 适配窄窗口：图标不能挤压产品名、右上角工具栏、子终端栏或对话输入；必要时允许工具栏缩短间距，但不能失去可访问名称。

### 3.3 UI 验收

- 1688×900 参考截图下，底部工具栏位置、图标尺寸和间距协调，不挡住子终端标题和“+”按钮。
- 1280×800、1024×768、宽度 760 以下分别验证；窄窗口允许合理压缩，但不能发生横向溢出或菜单出屏。
- 终端/对话面板交换顺序后，工具栏仍在左下角。
- 切换到仅终端、仅对话、分栏三种布局后，桌宠开关、主题和 GitHub 链接都可访问。
- 主题菜单从底部按钮上方弹出；点击主题后立即应用并保持原有持久化行为。
- 不再在右上角重复显示桌宠开关和主题入口。
- GitHub 按钮打开指定仓库；不会导航离开 Crescent 窗口或覆盖当前会话。

## 五、全项目功能性审查清单

这部分不是要求大规模重构，而是要求 Codex 结合当前源码、测试和运行证据逐项核验；只有发现明确缺陷时才修改，并为每项修复补回归测试。

### 5.1 应用启动、窗口和 Renderer 生命周期

- 检查 Electron 主进程启动、BrowserWindow 生命周期、renderer 崩溃恢复、重复 IPC 注册、退出时定时器/AbortController/PTY 清理。
- 检查主窗口缩放、切换布局、弹窗/Popover 层级、错误边界和 renderer 恢复界面。
- 检查开发态与打包态资源路径是否一致，lazy import 的组件和 WebM 资源在生产构建中是否可加载。
- 通过：首次启动、关闭再启动、切换页面/布局、Renderer 错误恢复时无白屏、无重复监听器、无遗留进程。

### 5.2 Electron IPC 与安全边界
